1背景：为什么需要 codespot

随着 AI 辅助编码在全行的普及，大量代码由开发人员借助行内外 AI 工具生成，在提效的同时引入了三类传统流程难以覆盖的风险：质量风险（逻辑缺陷、错误处理缺失，人工评审疲劳难以逐一把关）、安全风险（硬编码密钥、SQL 注入等漏洞模式频率显著偏高）、供应链风险（AI 倾向推荐携带已知 CVE 的旧版本依赖）。

🤖

仅靠 AI 模型扫描不够全面

大模型审查非确定性：无规则库兜底、无 CVE 数据库、无密钥特征库，存在漏报与幻觉；逐文件人工喂模型无法工程化。

🧱

传统工具游离于 AI Agent 生态之外

SonarQube 系等面向 CI/服务器架构，必须部署服务端；AI Agent 无法本地按需调用，更没有"扫描→报告→修复"闭环。

🇨🇳

国产化与自主可控要求

主流工具均为国外产品且许可趋紧（SonarSource 2024 年底改 SSALv1，明确限制"用非捆绑 AI 摄取分析结果"）；核心安全工具依赖外部供应商存在合规与供应链风险。

项目定位：建设纯本地运行、完全融入 AI Agent 生态、全栈开源引擎、代码完全自主可控的静态代码扫描 skill——AI 写完代码 → codespot 本地扫描 → AI 可读报告 → Agent 辅助修复 → 重扫验证，形成完整质量闭环。

2解决方案与方案设计

2.1 两轮可行性调研（结论先行）

启动前完成两轮系统调研（详见《可行性调研报告》，30+ 组件当日实测核验）：① Sonar 系路线证伪——官方 CLI 必须连云端/服务器，SSALv1"禁止非捆绑 AI 摄取分析结果"与核心场景直接冲突；② 采纳路线——干净许可开源引擎组合（MIT/Apache/LGPL）+"多引擎适配器+统一报告+AI 修复闭环"；③ 许可合规——引擎运行时从官方源下载、不随工具分发，LGPL 零额外义务，Semgrep/TruffleHog 明确仅内部使用边界。

3完全融入 AI Agent 生态（核心差异化）

codespot 不是"给人用的命令行工具顺便让 AI 调用"，而是以 AI Agent 为第一用户设计的 skill。一次真实使用闭环：

👤 开发人员 → 🤖 AI Agent（内置 codespot skill）
1自然语言触发"扫一下我刚生成的代码"——skill 自动识别，无需敲命令
2Agent 调用 CLIcodespot scan --scope auto（增量范围自动降级）
310 引擎并行按语言调度 · 失败隔离 · 秒到分钟级
4读机器报告report.json 完整字段，呈现前先判断发现合理性
5结构化选项严重 / 重要+ / 全部 / 先看详情（codespot show）
6Agent 修复逐条修复；密钥发现强制"先轮换后清理"
7重扫验证同 scope 重扫 ≤3 轮直至清零
8三类汇总已修复 / 跳过（含理由）/ 剩余
#融入层面实现
①技能即插即用标准 skill 目录，软链到 ~/.agents/skills/ 即被 ZCode 等 Agent 框架自动发现；自然语言（"扫一下代码 / 静态检查 / 有没有密钥泄漏"）自动触发
②Agent 专属接口report.json 保留 tool/rule/ruleUrl/fixHint 完整字段供 AI 精确研究与修复；密钥强制脱敏防二次泄漏
③交互修复闭环修复选项结构化问答；修复循环（判断合理性→修复→重扫→汇总）由 SKILL.md 编排
④AI 即引擎（首创）--engine ai 产出审查计划，Agent 本身作为第 10 个引擎执行语义级审查，结果经校验合并进统一报告
⑤误报治理Agent 判定误报可登记白名单（.codespot/ignore / .gitleaksignore），下次自动过滤
⑥零服务器纯本地 CLI，无需部署服务端与账号，任何 git 仓库即调即用
与"AI 直接读代码找问题"的本质区别：AI 引擎与规则引擎互补而非替代——确定性规则、CVE 数据库、密钥特征库由工具兜底，AI 只负责规则抓不到的语义问题（逻辑/并发/错误处理/跨文件一致性）；两类发现同场呈现、同一修复闭环。这直接补齐了"仅 AI 扫描不全面"的痛点。

投入极低、交付完整、验证充分；单次风险事件的避免即可覆盖全部成本。建议纳入 AI 编码标准工作流（AI 生成 → codespot 扫描 → 修复 → 提交）并在团队推广。

8边界与后续建议（如实说明）

  • Semgrep 规则许可限内部使用，工具不可对外销售/分发（已写入文档边界）；
  • Windows 需约一天适配（Semgrep 需 WSL2）；当前 macOS / Linux 验证充分；
  • TruffleHog 密钥活体验证默认关闭（合规考虑），需要时手动开启；
  • AI 语义审查发现为建议性（附 confidence），最终由人决策。
